# W-Feature

피처폰 게임을 구동하는 에뮬레이터입니다.  
KTF·LGT·SKT 게임을 지원합니다. SKT의 GNEX/GVM `.SGS` 실행 경로도 포함하며, 일부 서비스는 아직 지원하지 않습니다.

> [!IMPORTANT]
> ⚠️ **개발 중인 에뮬레이터입니다.**  
> 모든 게임을 지원하지는 않습니다.  
> 오류가 발생하면 디버그 로그와 함께 제보해 주시기 바랍니다.

서버를 기동한 뒤 웹 브라우저로 접속하며, PWA 설치를 지원합니다.  
기본 주소는 `http://127.0.0.1:11541`입니다.  
게임 파일을 폴더에 넣고 서버를 실행합니다.  
  
휴대폰에서는 브라우저로 서버에 접속하거나 apk·ipa를 설치합니다.  

---

## 0. 아카이브 다운로드 시  

[**Releases**](https://github.com/movingwoo/wfeature/releases)에서 운영체제에 맞는 파일을 받습니다.  
압축을 풀고, 안에 있는 `games/` 폴더에 게임을 넣고 실행합니다.  
폰에서는 화면의 **＋ 게임 추가** 버튼으로 넣습니다(지울 때도 같은 화면의 **게임 삭제**를 씁니다). iOS 앱은 파일 앱의 wfeature 폴더에 직접 넣을 수도 있습니다.  

| | 실행 | 처음 한 번 |
|---|---|---|
| Windows | `start.bat` 더블클릭 | SmartScreen → 추가 정보 → 실행, 방화벽 허용 |
| macOS | `start.command` 더블클릭 | Control-클릭 → 열기 (서명된 앱이 아님) |
| Linux | `./start.sh` | 권한 문제 시 `chmod +x start.sh wfeature-server` |
| Android | `.apk` 설치 | 출처를 알 수 없는 앱 허용 |
| iOS | `.ipa` 사이드로드 | AltStore·Sideloadly로 본인 Apple ID 서명 |

아카이브에는 `stop`·`status` 스크립트도 들어 있습니다(`stop.sh`·`stop.command`·`stop.bat` 등).  
서버 창을 닫았거나 이전에 기동한 서버가 남아 있을 때 사용합니다.  

사용법은 압축 안의 `README.txt`에 있습니다.  
아카이브를 직접 만들려면 `make dist`를 사용합니다.  
폰 빌드는 `make mobile`이며 안드로이드 SDK와 Xcode가 필요합니다. 한쪽 툴체인만 있으면 `make mobile-android`·`make mobile-ios`로 나눠 빌드합니다.  
릴리스 CI는 데스크톱 아카이브 다섯 개와 폰 빌드 두 개를 만들며, **일곱 개가 모두 만들어져야 발행합니다.**  
자세한 내용은 [`docs/running.md`](docs/running.md)에 있습니다.  
버전별 변경 내역은 [`CHANGELOG.md`](CHANGELOG.md) 문서에 있습니다.

## 1. 직접 빌드 시 준비물

저장소에서 직접 빌드할 때 필요한 것:

- **Go 1.26 이상** (`go version`으로 확인)
- (선택) **Node.js** — 페이지 테스트를 실행할 때만 사용

## 2. 게임 파일 넣기

저장소의 `var/games/` 아래에 넣습니다.  

플랫폼은 폴더 이름이 아니라 파일 내용으로 판별합니다.  
폴더 이름은 게임 목록의 분류 이름이 되며 자유롭게 정합니다.  
`var/games/`와 그 바로 아래 폴더 한 단계까지만 읽고, 더 깊은 폴더는 읽지 않습니다.

게임 선택 화면의 **＋ 게임 추가** 버튼으로도 넣을 수 있습니다.  
이 방식으로 넣은 파일은 `var/ext/`에 복사되며 원본은 그대로 남습니다.  
**화면의 게임 삭제 버튼은 `var/ext/`의 게임만 지웁니다.**  

## 3. 실행

```sh
make serve
```

빌드가 끝나면 브라우저에서 `http://127.0.0.1:11541`로 접속합니다.  
빌드가 이미 되어 있으면 서버만 실행합니다.

```sh
./build/debug/wfeature-server
```

`make serve`는 포그라운드로 실행되며 Ctrl-C로 종료합니다.  
백그라운드로 실행하려면 스크립트를 사용합니다.

```sh
./build.sh        # 빌드
./start.sh        # 백그라운드로 기동
./status.sh       # 실행 중인 서버와 포트 확인
./stop.sh         # 종료
```

인자가 없으면 **릴리즈 프로필**입니다.  
디버그 프로필은 `./build.sh debug`, `./start.sh debug`처럼 지정합니다.  
`./start.sh`의 나머지 인자는 서버에 그대로 전달됩니다(`./start.sh debug -addr 127.0.0.1:11599`).

`./status.sh`와 `./stop.sh`는 포트를 인자로 받으며(`./stop.sh 11599`), 스크립트 밖에서 기동한 서버도 정리합니다.  
포트 번호만으로 종료하지 않고, **그 포트의 서버가 wfeature인지 확인한 뒤에만** 종료합니다.

Windows에서 `make` 없이 실행하는 방법은 [`docs/running.md`](docs/running.md)에 있습니다.

주소와 폴더는 플래그나 환경 변수로 바꿉니다.

- 플래그: `-addr`, `-games`, `-ext`, `-saves`, `-logs`, `-web`, `-number`, `-open`, `-version` (`-port`는 `status`·`stop` 전용)
- 환경 변수: `WFEATURE_ADDR`, `WFEATURE_PORT`, `WFEATURE_HOST`, `WFEATURE_GAME_ROOT`, `WFEATURE_ADDED_ROOT`, `WFEATURE_SAVE_ROOT`, `WFEATURE_LOG_ROOT`, `WFEATURE_WEB_ROOT`, `WFEATURE_PHONE_NUMBER`, `WFEATURE_OPEN`

`-number`는 단말이 게임에 알려 주는 가입자 번호입니다. 요금제를 확인하는 일부 게임은 짧은 번호를 받으면 그 확인을 건너뜁니다.

### 소켓 방식

`-addr`에 `unix:`를 붙이면 포트 대신 유닉스 소켓 파일로 기동합니다.  

```sh
./build/release/wfeature-server -addr unix:/run/wfeature/wfeature.sock
```

소켓 파일은 `0660`으로 만들어지므로 프록시와 **그룹을 맞춰야** 합니다(systemd `Group=`).  
프록시 설정에서 **브라우저의 `Host` 헤더를 그대로 넘겨야 합니다.**  

`./start.sh`·`./stop.sh`·`./status.sh`는 포트를 기준으로 동작하므로 소켓 방식에는 사용할 수 없습니다.  
리버스 프록시 설정 예시와 systemd 유닛은 [`docs/running.md`](docs/running.md)에 있습니다.

## 4. 게임 시작하기

게임 목록에서 하나를 선택하고 **실행**합니다.  
첫 실행은 시간이 걸릴 수 있습니다.  

**🔄 재시작**은 현재 게임을 종료하고 새로고침 없이 게임 선택 화면으로 돌아갑니다.

서버는 실행 중인 게임과 대기 중인 게임을 합쳐 최대 4개까지 유지합니다.  

**세이브 내보내기 / 세이브 가져오기**로 세이브를 파일 하나로 주고받습니다. 자세한 내용은 [세이브](#세이브)에 있습니다.  

## 조작

키보드와 화면 키패드를 함께 사용할 수 있습니다.
게임의 문자 입력 칸을 선택한 뒤 **설정 → 🔤 문자 입력**을 누르면 휴대폰·PC의 기본 키보드와 한글 IME로 입력할 수 있습니다. 창에는 초록색 **입력 가능** 또는 빨간색 **입력 불가능**이 표시됩니다. 한글 조합을 마치고 **입력**을 누르면 게임에 반영됩니다. 기존 글자 뒤에 덧붙이는 입력 칸에서는 버튼이 **삽입**으로 표시됩니다.
단말 문자셋(KSC5601)에 없는 글자(이모지, 일부 한글)는 **입력 불가능**으로 거절합니다.

| 키보드 | 전화기 키 |
|---|---|
| 방향키 | 위 / 아래 / 왼쪽 / 오른쪽 |
| Space | 가운데(확인) |
| Backspace | 취소 (CLR) |
| \ | 통화 |
| M | 메뉴 (왼쪽 위 소프트키) |
| , | 우상단 (오른쪽 위 소프트키) |
| 1 2 3 | 1 2 3 |
| Q W E | 4 5 6 |
| A S D | 7 8 9 |
| Z X C | \* 0 # |

게임 도움말의 "좌측상단키"·"메뉴키"는 **메뉴**, "우측상단키"는 **우상단**입니다.
"확인키"·"OK키"는 가운데 키입니다(키패드의 **OK**, 키보드 매핑 목록의 **확인**).

위 표는 키보드 기본값이며, 설정의 **⌨️ 키보드 매핑 변경**에서 바꿀 수 있습니다.  
키패드 배치는 설정의 **🎮 키패드 타입**에서 고릅니다.  

디버그 빌드를 넓은 화면(PC 브라우저 등)에서 열면 화면 왼쪽에 실행 로그가 표시됩니다.

### 게임패드

게임패드를 연결하고 아무 버튼이나 한 번 누르면 사용할 수 있습니다. 브라우저는 버튼이 눌리기 전에는 패드를 페이지에 알리지 않습니다.

| 게임패드 | 전화기 키 |
|---|---|
| 십자키 / 왼스틱 | 위 / 아래 / 왼쪽 / 오른쪽 (왼스틱은 한 번에 한 방향) |
| 오른스틱 | 숫자 1~9 — 5를 둘러싼 8방향 (↖ 1, ↑ 2, ↗ 3, ← 4, → 6, ↙ 7, ↓ 8, ↘ 9) |
| A (아래 버튼) | 가운데(확인) |
| B (오른쪽 버튼) | 취소 (CLR) |
| X (왼쪽 버튼) | 5 |
| Y (위 버튼) | 0 |
| LB / RB | 메뉴 / 우상단 |
| LT / RT | \* / # |
| View | 통화 |
| Menu | 설정 열기·닫기 |
| L3 (왼스틱 누르기) | 연사 전환 |
| R3 (오른스틱 누르기) | 전체화면 켜기·끄기 |

버튼 이름은 Xbox 패드 기준입니다. 플레이스테이션·닌텐도 패드는 **같은 위치**의 버튼이 대응합니다(A 위치 = ✕ = 닌텐도 B).
설정의 **🕹️ 게임패드 매핑 변경**에서 버튼마다 보낼 키를 바꿀 수 있으며, 패드 버튼을 누르고 있는 동안 해당 줄이 밝게 표시됩니다. 퀵세이브·퀵로드도 여기서 지정합니다(기본값은 비어 있음).
브라우저가 표준 배치로 인식하지 못하는 패드는 처음에 모든 줄이 비어 있으므로 같은 메뉴에서 직접 지정합니다. 십자키가 축 하나로 들어오는 패드는 `십자 ↑ (축 10)`처럼 네 줄로 표시됩니다.
게임이 진동을 요청하면 패드도 진동합니다(**📳 진동** 설정을 따름).
휴대폰 브라우저에서 `http://192.168.…` 주소로 연 페이지에서는 브라우저가 게임패드를 차단합니다. PC에서 `localhost`/`127.0.0.1`로 연 페이지, 안드로이드·iOS 앱, `https` 주소에서는 사용할 수 있습니다.

### 전체화면

키패드를 숨기고 게임 화면을 창에 맞춰 최대로 키웁니다. 게임패드나 키보드로 조작할 때 사용합니다.

- 켜기: **설정 → ⛶ 전체화면**, 게임패드 **R3**, 또는 **🎮 키패드 세부 조정**에서 칸에 **전체화면**을 넣고 누르기
- 끄기: 화면 오른쪽 위의 `[ ]` 모양 버튼, **Esc**, 게임패드 **R3**, 또는 설정의 **⛶ 전체화면 끝내기**
- 전체화면에서도 게임패드 **Menu** 버튼으로 설정을 열 수 있습니다.
- 다시 열어도 마지막 상태가 유지됩니다.

## 설정

키패드의 빨간 `설정` 키를 누릅니다. 기본 위치는 윗줄 맨 왼쪽입니다.

- **🎵 배경음 / 🔊 효과음** — 배경음과 효과음 음량. 브라우저별로 기억합니다.
- **🔍 화질** — 원본 / hq2x / hq3x / hq4x. 배율이 높을수록 느려집니다.
- **📱 화면** — 게임이 인식하는 단말 화면 크기. 128×160, 176×220, 240×320(기본), 240×400, 320×480 중에서 고르며 다음 실행부터 적용됩니다. 작은 단말용으로 만든 게임은 그 크기를 골라야 그림을 제대로 불러옵니다. 확대 기능이 아니며, 큰 화면을 주었을 때 화면 전체를 쓰는지 240×320 그림만 그리는지는 게임마다 다릅니다.
- **🎮 키패드 타입** — `Type1` / `Type2` / `Type3` / `Type4` 중에서 고릅니다.
- **🎮 키패드 세부 조정** — 격자에 키를 지정하고 여러 칸을 합쳐 버튼 크기와 모양을 바꿉니다. 퀵세이브·퀵로드·전체화면도 원하는 위치에 추가합니다. [키패드 크기와 모양 바꾸기](#키패드-크기와-모양-바꾸기) 참조.
- **⛶ 전체화면** — 키패드를 숨기고 게임 화면을 최대로 키웁니다. [전체화면](#전체화면) 참조.
- **📳 진동** — 게임이 요청한 진동을 실제로 울릴지 정합니다. 진동을 지원하지 않는 브라우저에서는 표시되지 않습니다.
- **⏩ 속도** — 0.25배~4배.  
- **⌨️ 키보드 매핑 변경** — 키보드 키 배정을 바꿉니다.  
- **🕹️ 게임패드 매핑 변경** — 게임패드 버튼 배정을 바꿉니다. 패드를 한 번 사용하면 표시됩니다.
- **🎯 치트** — [치트](#치트) 참조.
- **🐞 디버그 로그 저장** — 디버그 빌드에서 로그를 서버에 저장합니다.
- **🔤 문자 입력** — 게임의 문자 입력 칸에 휴대폰·PC 키보드로 입력합니다. [조작](#조작) 참조.
- **🔄 재시작** — 게임 선택 화면으로 돌아갑니다.

### 키패드 크기와 모양 바꾸기

**설정 → 🎮 키패드 세부 조정**에서 편집합니다. 편집 중에는 게임에 키 입력을 보내지 않습니다.
격자는 **14열×9행**이며, 기본 버튼 하나가 가로 두 칸을 차지합니다. 반 칸 단위로 조정하려면 버튼을 **나누기**로 나눈 뒤 원하는 칸에 키를 지정합니다.

1. 버튼이나 빈 칸을 누르고 넣을 키를 고릅니다.
2. **여러 칸 선택**을 누르고 합칠 칸을 누르거나 드래그합니다. 다시 누르면 선택이 풀립니다.
3. **합치기**를 누릅니다. 서로 다른 키를 골랐다면 합친 버튼에 넣을 키를 먼저 고릅니다.

합치기가 끝나면 **여러 칸 선택**이 해제되고 합친 버튼이 선택되므로, 이어서 키를 누르면 바로 지정됩니다.

변을 맞댄 칸은 직사각형·L자·T자·가운데가 빈 모양으로 합칠 수 있습니다. 빈 모서리나 구멍은 눌리지 않으며, 그 자리에 다른 키를 넣을 수 있습니다.
이미 합친 버튼은 통째로 선택됩니다. 일부 칸만 바꾸려면 먼저 **나누기**를 누릅니다.

- **나누기** — 한 칸씩 나누고 맨 위·왼쪽 첫 칸에만 기존 키를 남깁니다.
- **비우기** — 버튼 모양은 유지하고 키만 지웁니다.
- **되돌리기** — 편집 중 마지막 변경 한 번을 취소합니다.
- **기본값으로 되돌리기** — 현재 타입만 기본 배치로 되돌립니다.

설정 버튼은 항상 하나 남습니다. 다른 칸에 **설정**을 지정하면 그 칸으로 옮겨집니다.
Type1~Type4는 각자 배치를 기억합니다. 이전 버전에서 저장한 배치도 새 격자로 옮겨집니다.
Type1~Type3의 기본 윗줄은 1~2칸이 **설정**, 13~14칸이 **취소**로 합쳐져 있고 3~12칸은 한 칸씩 나뉩니다. 5~10칸은 순서대로 **퀵세이브·퀵로드·연사·메뉴·통화·우상단**이며 3·4·11·12칸은 빈 칸입니다.
**연사**는 누를 때마다 끔·수동·자동 순서로 바뀝니다. 수동은 `5`·`OK`를 누르고 있는 동안 초당 10번 반복하고, 자동은 `5`나 `OK`를 한 번 누르면 다시 누를 때까지 반복합니다. 자세한 동작은 [`docs/rapid-fire.md`](docs/rapid-fire.md)에 있습니다.
저장된 배치 대신 새 기본 배치를 쓰려면 해당 타입에서 **기본값으로 되돌리기**를 누릅니다.
버튼 이름은 한 줄로 표시되며 칸 너비에 맞춰 글자 크기가 줄어듭니다. 글자가 너무 작으면 여러 칸을 합쳐 버튼을 키웁니다.
키패드는 좌우 여백 없이 게임 영역의 가로폭(최대 480px)과 게임 화면 아래 남은 높이를 채웁니다. 키 크기·좌우 비율은 슬라이더가 아니라 칸 합치기로 조정합니다.

실제 사용 가능한 공간은 기종·OS·주소창·홈 바에 따라 다릅니다. 화면 가장자리의 안전 영역을 비우고 남은 공간에 같은 14열×9행을 맞추므로, 화면을 회전하거나 주소창이 접혀도 배치는 유지됩니다.

## 세이브

게임 안에서 저장하면 아래 경로에 기록됩니다.

```
var/savedata/<빌드 프로필>/<플랫폼>/<게임 ID>/
```

`<게임 ID>`는 KTF·LGT는 PID, SKT는 프로그램 번호입니다.  
debug 빌드와 release 빌드는 세이브 폴더가 서로 다릅니다.  

게임 선택 화면의 **세이브 내보내기**는 이 폴더를 `.wfs` 파일 하나로 묶어 내려받고, **세이브 가져오기**는 그 파일로 세이브를 되돌립니다.  

### 퀵세이브 (KTF·LGT·SKT)

KTF·LGT·SKT 게임에서 사용할 수 있습니다. SKT는 Java 게임과 GNEX/GVM SGS 게임을 모두 지원합니다.

**설정 → 🎮 키패드 세부 조정**에서 원하는 칸에 **퀵세이브**와 **퀵로드**를 배치합니다.
Type1~Type3은 기본 윗줄 5·6칸에 퀵세이브·퀵로드가 있습니다. Type4는 원하는 칸에 직접 추가하며, 배치는 브라우저에 저장됩니다.
게임 실행 중 **퀵세이브**를 누르면 현재 실행 상태(화면·진행·소리·입력)를 저장하고,
**퀵로드**를 누르면 게임이 그 시점으로 돌아갑니다.
확인 창 없이 바로 실행되며, 결과는 화면 아래에 잠시 표시됩니다.
게임 파일 하나에 퀵세이브 하나를 유지하며, 다시 저장하면 덮어씁니다.

퀵로드는 **게임 내 세이브를 되돌리지 않습니다.** 게임만 퀵세이브 시점으로 돌아가고, 세이브는 지금 저장된 그대로 둡니다.

- 퀵세이브 뒤에 게임에서 저장한 세이브는 퀵로드 후에도 남습니다.
- 퀵로드 후 게임이 세이브를 읽으면 지금 저장된 내용을 읽고, 게임이 저장하면 그 위에 기록합니다. 나중에 한 저장이 남습니다.
- 게임이 쓰는 중이던 세이브(아직 닫지 않은 파일에 쓴 내용)는 퀵세이브와 퀵로드 직전에 먼저 디스크에 기록합니다. 기록하지 못하면 퀵세이브·퀵로드를 거절하고 게임은 그대로 진행합니다.

퀵로드는 게임을 퀵세이브 시점의 메모리 상태로 되돌립니다. 따라서 다음은 게임 자체의 동작이며 에뮬레이터가 보정하지 않습니다.

- 세이브 목록을 메모리에 들고 있는 게임은 퀵로드 직후 목록이 이전 상태로 보일 수 있습니다. 세이브 파일은 그대로이며 게임을 다시 실행하면 표시됩니다.
- 퀵로드 후 게임이 저장하면(자동 저장 포함) 그 내용이 현재 세이브 위에 기록됩니다. 세이브의 일부만 다시 쓰는 게임은 서로 다른 시점의 내용이 한 세이브에 섞일 수 있습니다.
- 게임이 저장하는 도중에 만든 퀵세이브는 불러올 때마다 남은 저장 동작을 현재 세이브 위에 다시 실행합니다. 저장 중에는 퀵세이브를 사용하지 않아야 합니다.
- 자동 백업은 없습니다. 보존할 세이브는 **세이브 내보내기**로 따로 보관합니다.

서버를 다시 기동한 뒤에는 게임을 실행하고 **퀵로드**를 누릅니다.
퀵세이브는 `.wfs` 백업에 포함되지 않습니다. 게임 파일이 바뀌었거나 호환되지 않는 퀵세이브는
이유를 표시하고 거절하며, 파일은 지우지 않습니다. 불러오기에 실패하면 실행 중인 게임은 그대로 진행되고 세이브도 바뀌지 않습니다.

퀵세이브 형식은 debug와 release가 같으며, 같은 저장 경로를 지정하면 서로 불러올 수 있습니다.
버전이 바뀌어 형식이 달라지면 이전 퀵세이브를 불러오지 못할 수 있습니다(파일은 지우지 않음). 게임 내 세이브는 영향받지 않습니다.
지원하지 않는 실행 상태이거나 치트 고정·패치가 켜져 있으면 퀵세이브를 거절합니다.
소리는 멈춘 위치부터 이어서 재생합니다. 다만 소리를 다시 합성하므로 음색의 위상이나 이미 울린 음의 잔향은 새로 시작될 수 있습니다.

## 치트

게임 메모리 값을 찾아 바꾸는 도구입니다.  
값을 바꿔 가며 후보 주소를 좁혀 찾습니다.  

1. 게임에서 바꾸려는 값(예: 소지금)을 확인합니다.
2. 치트 패널에 그 숫자를 넣고 **이 값으로 찾기**를 누릅니다.
3. 게임으로 돌아가 값을 바꿉니다.
4. 새 값을 넣고 다시 **이 값으로 찾기**를 누릅니다. 후보가 몇 개로 줄어들 때까지 반복합니다.

찾은 주소를 **고정**하면 그 값이 계속 유지됩니다.  
**쓰기 감시**에 주소를 넣으면 그 값을 바꾸는 코드가 표시됩니다.  
찾은 값 목록은 **저장**·**불러오기**할 수 있습니다.

# 개발자용

이하 내용은 저장소에서 직접 빌드·개발하는 경우에 해당합니다.  
기술 문서는 모두 `docs/` 아래에 있습니다.

## 빌드 프로필

개발용·운영용 서버를 따로 두지 않고 같은 코드를 두 프로필로 빌드합니다.  
debug는 로그와 진단을 모두 포함하고 release는 진단을 최소화합니다.  
프로필마다 출력 폴더가 달라 서로 덮어쓰지 않습니다.

| 명령 | 결과물 |
|---|---|
| `make debug` | `build/debug/wfeature` |
| `make release` | `build/release/wfeature` |
| `make server` | `build/debug/wfeature-server` — 웹 자산이 들어 있는 단일 실행 파일 |
| `make server-release` | `build/release/wfeature-server` |

프로필을 고르는 플래그는 없으며, 실행한 바이너리가 곧 프로필입니다.

```sh
make serve              # 디버그
make serve-release      # 릴리즈
```

`make dist VERSION=0.5.2`처럼 버전을 지정하면 다섯 OS·아키텍처(darwin/arm64, darwin/amd64, linux/amd64, linux/arm64, windows/amd64)용 아카이브를 만듭니다.
`v`로 시작하는 태그를 푸시하면 GitHub Actions가 같은 아카이브를 만들어 릴리스에 올립니다. 푸시마다 우분투·윈도우·macOS에서 서버를 실제로 기동해 확인합니다.  
자세한 내용은 [`docs/running.md`](docs/running.md)에 있습니다.

## CLI

브라우저 없이 게임을 실행하는 개발·진단 도구입니다.  
서버와 같은 에뮬레이터를 사용하며 tick 수 지정·재현 스크립트·프로파일러·GDB 연결을 지원합니다.

```sh
make run ARGS="runktf var/games/ktf/game.zip -play"
```

`runktf`, `runskt`, `runlgt`는 브라우저와 같이 인증 호환을 자동 적용하며, 비교 진단할 때만 `-no-auth`로 끕니다. 결과는 `authentication: ktf-certificate-52`, `authentication: skt-license`처럼 표시되고, `unsupported`는 지원하는 방식을 찾지 못했다는 뜻입니다. LGT는 `lgt-cached-authentication`, `lgt-certificate-58`, `lgt-certificate-100`, `lgt-offline-notification`, `lgt-offline-authentication`, `lgt-save-subscriber`, `lgt-certificate-message`로 표시됩니다. `lgt-offline-notification`과 `lgt-offline-authentication`은 게임 화면에서 고른 동의 여부나 연결 확인 요청을 로컬에서 처리합니다. 외부로 전송하지 않으며, 게임이 안내하는 재시작은 필요할 수 있습니다.

`-framedir`로 남긴 프레임은 `contactsheet`로 한 장에 모으고, `framediff`로 두 빌드를 비교하며, `zoom`으로 한 프레임의 일부를 확대합니다.  
`framestats`는 프레임에 그려진 내용을 색 수와 켜진 픽셀 수로 보고하며, 모든 프레임이 단색이면 0이 아닌 종료 코드를 반환합니다.  
명령과 플래그 전체, 재현 스크립트와 `ktfdump`는 [`docs/cli.md`](docs/cli.md)에 있습니다.

## 화면 문구

페이지에 보이는 문구는 키 이름, 버튼, 안내문, 서버가 보내는 거절 문구까지 전부 [`web/text.properties`](web/text.properties) 한 파일에 있습니다.  
한 줄에 `키 = 문구` 하나이고, `{count}`처럼 중괄호로 쓴 자리에는 보여 줄 때 값이 들어갑니다.  
`make serve`처럼 저장소의 `web/`을 쓰는 서버는 파일을 고친 뒤 새로고침만 하면 바뀐 문구가 보이고, 실행 파일에는 빌드할 때 들어갑니다.  
형식과 규칙은 [`web/README.md`](web/README.md#text)에 있습니다.

## 테스트

```sh
make test          # go test + Node 테스트
make test-debug    # 디버그 빌드 태그로 go test
make acceptance    # 로컬 게임 아카이브를 전부 실행하고 보고서 작성
```

`make acceptance`는 `var/games/` 아래 아카이브를 플랫폼별로 끝까지 실행하고
`var/acceptance/<날짜>.md`에 각 게임이 어디서 멈췄는지 기록합니다. 저장소에는 게임이 없으므로
로컬에 게임 아카이브가 있어야 실행할 수 있고, 그래서 `make test`에 포함되지 않습니다.

검증 범위는 [`docs/testing.md`](docs/testing.md)에 있습니다.
